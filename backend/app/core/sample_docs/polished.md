# LiMo 深度说明 —— 引擎、检索、模型与插件

> 这是「整理版原文」页，面向想深入了解 LiMo 工作机制的用户。
> 包括：处理链路、各类转换引擎、检索原理、大模型选择、如何接入自定义大模型，以及插件系统。

---

## 一、LiMo 是怎么工作的

一条输入会经历 **三层管道**：

```text
输入（URL / 文本 / 文件）
   ↓ ① 适配器提取正文（Adapter）
原始转录（transcript）
   ↓ ② 引擎转换 + LLM 生成
产物（笔记 · 整理版原文 · 追问建议）
   ↓ ③ 保存 / 导出
```

- **适配器**：按内容类型自动路由（视频 / 文档 / 图片 / 网页 / 文本）
- **引擎**：负责「看懂」原始内容 —— 语音转写、OCR、文档解析、向量编码
- **大模型**：负责「写好」最终产物 —— 笔记、整理、对话、多篇合成

## 二、转换引擎详解

引擎在「设置 → 模型 & 引擎」中配置，按场景绑定。内置引擎均为 **MIT / BSD 宽松协议**（向量引擎是例外，它不按场景绑定，而是在 设置 → 通用 → 检索索引 里单独开关）。

### 📄 文档引擎（Doc）

| 引擎 | 协议 | 用途 | 说明 |
|------|------|------|------|
| **pypdfium2** | BSD-3 | PDF（默认） | C 引擎直读文字 + 嵌入原图，毫秒级 |
| **pdf-image** | BSD-3 | 扫描 PDF | 整体转图片：渲染每页 PNG 嵌入 MD，供 OCR / 多模态 |
| **pdfplumber** | MIT | PDF 表格 | 辅助提取表格结构 |
| **markitdown** | MIT | Office / EPUB | 一键转 Markdown |
| **python-docx** | MIT | Word | 文字 + 表格 + 图片 |
| **python-pptx** | MIT | PPT | 文字 + 图片 + 备注 |
| **openpyxl** | MIT | Excel | 表格数据提取 |
| **epub-container** | 自研 | EPUB | 章节 + 图片 + 元数据（纯标准库） |

> AGPL 协议引擎（如 PyMuPDF4LLM）以**插件**形式提供：从 GitHub 仓库安装后，在独立进程的虚拟环境中运行，与主程序隔离。

### 🎙 语音转写引擎（ASR）

| 引擎 | 类型 | 需要 Key | 说明 |
|------|------|---------|------|
| **bcut-asr** | 云端免费 | ❌ | B 站必剪转写，中文优化，开箱即用 |
| **dashscope-asr** | 云端 | ✅ DashScope | 阿里云 Paraformer，识别质量高 |

> 本地转写引擎（faster-whisper 等）已改为**可选安装**：体积大、CPU 慢、GPU 依赖笨重，不适合随安装包分发。需要本地转写的用户可自行安装。

### 🔍 OCR 引擎（图片文字提取）

| 引擎 | 类型 | 需要 Key | 说明 |
|------|------|---------|------|
| **dashscope-ocr** | 云端 VL | ✅ DashScope | 视觉大模型提取，支持复杂版面 |

> Tesseract 已从内置移除（2026-08-02）——无 DashScope key 时扫描件 OCR 出占位文本；需要本地 OCR 请安装三方插件（参考模板 `backend/plugins/examples/tesseract_plugin.py`）。
>
> 引擎绑定只取第一个可用引擎，失败直接报错（换引擎请在设置页手动切换）。文档生成时还能用 OCR 把图片里的文字塞回原文。

### 🧭 向量引擎（Embedding，用于语义检索）

| 引擎 | 类型 | 需要 Key | 说明 |
|------|------|---------|------|
| **dashscope-embedding** | 云端 | ✅ DashScope | `text-embedding-v4`，1024 维，按字数计费 |
| **local-bge-small** | 本地 | ❌ | bge-small-zh-v1.5（ONNX int8），512 维，免费、零外发 |

> 这两个引擎是**可选能力**，不随安装包分发。云端引擎只要填了 DashScope Key 就能用；本地引擎需要自己准备运行环境——`onnxruntime` 与 `tokenizers` 两个 Python 包，以及放在 `~/.limo/models/bge-small-zh-v1.5-onnx/` 的模型文件。**缺什么、为什么用不了，设置页会直接写出来**，不会假装可用。两种引擎算出来的向量不能混用，切换后需要重建一次向量索引。

## 三、检索：全文与语义

默认的检索是**全文检索**——不花钱，也不需要额外配置：

- 索引的内容是**原文 + 最新版笔记**，所以「你写过的东西」和「来源内容」都搜得到
- 查询按中文二字组切分着匹配，不是整词比对：搜「机器学习」和搜「机器」都能命中
- 索引存在本机 `~/.limo/search.db`，文档改动后自动更新，删除文档时对应索引一并清掉
- 万一索引文件损坏，打开文档库时顶部会直接说明，旁边就有「重建索引」按钮（想看得更细，**设置 → 通用 → 检索索引** 里有篇数、体积和上次重建时间）

**语义检索（向量）**是可选项，默认关闭。开启后，搜索会把「字面命中」与「意思相近」两路结果融合排序——一个词都没出现、但讲的是同一件事的文档也可能被找出来。做法是把每篇文档切块后编码成向量，查询时算相似度，再按排名与全文检索的结果融合。

- 编码由**向量引擎**完成（见上表），云端或本地任选
- 首次开启或换模型后需要**全库建一次索引**，此后只编码新增和改动过的块
- 索引存在 `~/.limo/vec.db`，里面记着模型、维度、切块大小、格式版本四项身份信息——任何一项对不上都视为不可用。此时**不会自动重建**（编码是计费调用），而是提示你手动点「重建向量索引」
- 用本地引擎时还能决定**模型算完之后要不要留在内存里**：常驻（之后每次搜索都不必等，代价是几十 MB 一直占着）、闲置后释放（默认，省内存）、建完即释放（下一次搜索要等几秒重新载入）

## 四、大模型选择

### 内置厂商

| 厂商 | 说明 |
|------|------|
| **DeepSeek** | 默认，1M 上下文，性价比高 |
| **通义千问（DashScope）** | 含多模态 / OCR 模型 |
| **OpenAI / Anthropic / Google** | GPT / Claude / Gemini |
| **智谱 GLM / Moonshot Kimi** | 国内可直连 |

### 场景绑定

大模型按三个场景分别配置（设置 → 模型 & 引擎 → 场景模型）：

| 场景 | 用途 |
|------|------|
| **生成笔记** | 笔记 / 整理版原文 |
| **AI 对话** | 对话助手 + 联网工具 |
| **图片处理** | OCR / 表格 / 图片理解（**必须用多模态模型**）|

> 多模态模型需要把能力标记为「多模态」，图片处理场景才能调用。

## 五、如何接入自定义大模型

LiMo 支持 **OpenAI 兼容接口** 的任何模型服务（本地 Ollama / vLLM、第三方中转站、自建网关等）。

### 图形界面方式

1. 打开 **设置 → 模型 & 引擎**
2. 在「大模型」区域点 **添加厂商**，填写：
   - **名称**：自定义标识，如 `my-gateway`
   - **接口地址（base_url）**：OpenAI 兼容端点，如 `http://127.0.0.1:11434/v1`
   - **API Key**：本地服务留空，云端中转站填对应 Key
3. 点 **拉取模型** 自动获取可用模型，或手动添加模型名
4. 在模型列表中 **启用** 该模型，并标记能力（纯文本 / 多模态）
5. 回到「场景模型」，把生成 / 对话 / 图片处理绑定到该模型

### 直接改配置文件

在数据目录（`~/.limo`）的 `config.yaml` 中添加：

```yaml
providers:
  - id: my-gateway
    name: 我的网关
    type: openai
    base_url: http://127.0.0.1:11434/v1
    api_key: ""
llm_models:
  my-gateway:
    - id: qwen3
      name: Qwen3
      capabilities: [text]
```

> ⚠️ 自定义厂商需提供 OpenAI 兼容的 `/chat/completions` 接口；能力标签影响「图片处理」是否可用。

## 六、插件系统

核心系统只保留轻量、稳定的能力；依赖重、协议有风险、跨平台难维护的东西，通过插件接进来。插件由三方发布，主程序只维护**契约与加载机制**，不随主程序迭代，也不由官方维护。

- **安装**：把插件目录放到 `~/.limo/plugins/`，或在 设置 → 插件 里选一个 zip 包安装，重启后端生效；删除目录即完全卸载
- **两种运行形态**：**进程外**（默认，在独立虚拟环境里跑，依赖与崩溃都隔离）与**进程内**（插件作者显式声明 `trusted`，权限等同主程序）
- **已支持的类别**：文档引擎、图片识别、语音转写
- 插件可以声明自己需要的配置项，设置页会据此生成表单

**插件会自检自己能不能跑。** 有些插件装得上却用不了——缺外部程序（比如 tesseract）、缺模型文件、缺 API Key。这类问题会直接写在**设置页的插件卡片上**（「不可用：缺少 xxx」），不必等你选完引擎、点完生成才发现。自检不通过的插件仍然可以启用和绑定，只是会一直带着这条提示。

## 七、数据与隐私

- 所有数据默认保存在**本机数据目录**（`~/.limo`），不强制上传
- API Key 在配置中**脱敏存储**（Windows 上另存进系统凭据库），接口返回时打码
- 图片 / 视频 / 文档解析均在本地或你配置的云端服务完成
- 全文索引与向量索引都存在本机；删除文档时对应索引一并清掉
- **开启云端语义检索后**，文档正文与最新版笔记会发送到你所选的模型服务商做编码；改用本地引擎则这部分完全不出本机
- **插件是三方代码**，运行权限与主程序相同（进程内）或在独立虚拟环境里（进程外），请只安装你信任的插件
- 请定期备份数据目录，并妥善保管你的 API Key
